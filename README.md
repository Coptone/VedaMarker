# VedaMarker

VedaMarker is a standalone Dalamud plugin for the DMU P2 **Forsaken** encounter.
The current testing milestone provides deterministic role inference, automatic
eight-wave status recognition, dry-run marker assignments, an opt-in experimental
native Party Marker queue, a manually controlled local ground-range simulator,
and a privacy-preserving whole-duty evidence recorder.

## Current status

- P0 scaffold, manual controller, and redacted capture workflow: implemented and captured in game
- P1 role inference, Forsaken state machine, automatic wave recognition, and marker rules: implemented and unit tested
- Real party target markers: opt-in experimental native provider with self-only (default), selected-role, and full-party modes; disabled by default pending an in-game submission/cleanup PoC
- Local ground-range simulator: implemented for solo testing in any duty; manually selects Wave 1-8 and Direction 0-7
- Persistent native VFX: blocked on captured resource evidence
- Automatic encounter AoE telegraphs: blocked on per-mechanic timing and orientation validation

The plugin never moves the player, simulates input, or executes combat actions.
The real encounter controller requires manual role confirmation, an explicit
experimental toggle, and manual controller arming. Role confirmation is retained
across wipes and duty recommences within the same instance; the controller still
stops and must be manually restarted. Leaving the instance or an actual
party-composition change resets confirmation. Each plugin instance computes the
complete eight-person assignment. At the start of every wave it first clears every
selected target, then applies every selected target's new marker. The default
selection is the local player; selected-role and full-party modes require an
explicit choice.
The experimental provider does not submit chat commands. It scans for the native
marking function, uses `MarkingController` to read the current marker, and toggles
that exact marker to clear it. If the native function or controller is unavailable,
real marking fails closed and cannot be enabled.

The UI includes a manually started diagnostic that tests all eight real marker
types on the local player. For each type it reads the game's marker state,
clears the marker, reads the cleared state, and displays the per-item result.
It also shows the currently observed local marker and the most recent native
operation.

A separate cross-duty simulator can be used in O8S or any other duty. In
self-only mode it can run with one player: the user selects a simulated role and
the provider resolves only the local actor, without requiring party slots or role
confirmation. Selected-role and full-party simulation still require a confirmed
eight-player party. Each synthetic wave is generated by the same odd/even
assignment resolver and uses the same clear-before-mark provider as the real
encounter. It never advances itself.

Transitions in either direction between marking and clearing wait at least
750 ms. Operations within the same clear phase or marker phase continue to use
the configured queue interval.

The local AOE simulator is independent from real party markers. It anchors a
synthetic arena center at the user's current position and draws the supplied
odd/even strategy station names, 90-degree 30m cones, and 5m circles through
world-to-screen projection. It is visible only to the local user and continues
when the control window is closed. This validates geometry and readability; it
does not claim automatic DMU timing/orientation is complete.

The built-in redacted recorder is started manually and never uploads data. It
exports a schema-v2 local ZIP containing session aliases, jobs/roles, statuses,
all observed cast and ActionEffect IDs with localized names when available,
positions/rotations/hitboxes, target locations, map effects, and periodic world
snapshots, without character names, account/Content IDs, worlds, or chat.

## Install with Dalamud

Add the following URL under Dalamud Settings -> Experimental -> Custom Plugin
Repositories, then search for `VedaMarker` in the plugin installer:

```text
https://raw.githubusercontent.com/Coptone/VedaMarker/main/pluginmaster.json
```

The published package is a testing build. Experimental real party markers are
disabled by default and default to self-only when enabled. Persistent native VFX
and automatic encounter AoE telegraphs remain unavailable until their separate
in-game evidence gates pass.

For a solo O8S simulation test, set the target scope to `仅自己`, enable real
markers, choose the local simulated role, then use `跨副本模拟测试` to arm and
submit each wave manually. Finish with `结束模拟并清理`. Custom-role and
full-party testing still require a complete confirmed eight-player party.

For a solo AOE display test, enter any duty, open `/vedamarker`, and click
`以本人当前位置启动 AOE 模拟`. Change Wave and Direction while watching the
ground drawing; use `把模拟中心移到本人当前位置` whenever a clearer area is
needed. This feature does not require real markers to be enabled.

## Repository layout

```text
src/VedaMarker.Core          Game-independent rules and state
src/VedaMarker               Dalamud adapter, UI, and recorder
tests                         Core-rule and capture-privacy tests
docs                         Architecture, progress, and capture instructions
```

## Build

Core logic only:

```powershell
dotnet test tests/VedaMarker.Core.Tests/VedaMarker.Core.Tests.csproj -c Release
```

Full plugin builds also require a matching official Dalamud development
distribution and `DALAMUD_HOME`.
